# Ansible — the Elastic Stack and the agents

Configures the monitoring VM (single-node Elasticsearch, Kibana, Fleet Server,
Prometheus exporters) and enrolls a Fleet-managed Elastic Agent on **every**
host in the homelab — including hosts other repos own. The end-to-end steps
and the "why" are in [../RUNBOOK.md](../RUNBOOK.md); this doc covers the
`ansible/` component on its own.

## Layout

```text
playbooks/
  site.yml                      imports every numbered playbook, in order
  00-bootstrap.yml              colac.homelab.common, elastic_preflight,
                                colac.homelab.docker_data — `monitoring` only
  20-elastic-certs.yml          es_certs — internal CA + node cert, CA to all
  25-elasticsearch.yml          elasticsearch
  30-elasticsearch-security.yml es_security_bootstrap
  35-kibana.yml                 kibana_tls (Let's Encrypt), then kibana
  40-fleet-server.yml           fleet_bootstrap, then fleet_server
  45-exporters.yml              exporters (before the agents start scraping)
  50-elastic-agent.yml          elastic_agent, on every host
  99-healthcheck.yml            read-only verification; safe to run any time
inventory/            DIRECTORY inventory — every file inside is merged
  monitoring.yml      generated by Terraform (git-ignored)
  hosts.yml           hand-authored agent targets (git-ignored; see .example)
  group_vars/         hand-authored; Terraform never writes here
roles/                elastic_preflight, es_certs, elasticsearch,
                      es_security_bootstrap, kibana_tls, kibana,
                      fleet_bootstrap, fleet_server, exporters, elastic_agent
collections/          installed by `mise run setup` (git-ignored), incl.
                      colac.homelab from the core repo
files/truenas/        vendored config applied to the NAS by hand
.certs/               generated CA + node cert (git-ignored)
.secrets-cache/       Fleet service + enrollment tokens (git-ignored)
```

Run everything through mise, from anywhere in the repo:

```bash
mise run inventory                       # confirm the merge
mise run play playbooks/site.yml         # credentials for this run only
mise run play playbooks/35-kibana.yml --check --diff
```

A bare `ansible-playbook` gets no credentials — `elastic_preflight` then fails
and says so. See [Secrets](../README.md#secrets).

## Who owns which host

| Group | Comes from | What runs on it |
|---|---|---|
| `monitoring`, `elasticsearch`, `kibana` | `inventory/monitoring.yml`, generated by `terraform/` | Everything — this repo owns the VM |
| `agents` | `inventory/hosts.yml`, hand-authored | Only the plays on `all`: the CA (`20`) and the agent (`50`) |

Agent targets are VMs another repo provisions and configures — today the
Nextcloud VM from the workloads repo. This repo never prepares their disks,
Docker or apps; it only enrolls them, which is why observability can be
rolled out, and broken, independently of what it watches. Adding one is a
`hosts.yml` entry plus `mise run play playbooks/20-elastic-certs.yml
playbooks/50-elastic-agent.yml --limit <host>`.

### Why the inventory is a directory

Terraform writes `monitoring.yml`; you write `hosts.yml`. A directory
inventory merges them, so neither writer can clobber the other.
`ansible.cfg` adds `.example` to `inventory_ignore_extensions` so the tracked
`hosts.yml.example` is not parsed as a real source.

The inventory host names deliberately differ from the Proxmox VM names
(`monitoring-vm`, `nextcloud-vm`): Ansible warns and resolves ambiguously when
a host and a group share a name.

The monitoring host is in **three** groups at once — `monitoring`,
`elasticsearch` and `kibana` — because it genuinely plays all three roles the
six-VM cluster spread across machines. Keeping the group names identical to
that cluster's is what let its roles port over with their
`groups['elasticsearch'][0]` lookups intact.

## Shared roles from the core repo

`colac.homelab.common` (generic preflight) and `colac.homelab.docker_data`
(the LVM data disk, containerd's image store included) come from the core
repo, pinned in `requirements.yml` to a release tag. Their documentation lives
there: [colac.homelab](https://github.com/colac/homelab-proxmox/blob/main/ansible/README.md).

To try an unreleased change to them, `mise run deps:dev` installs the sibling
`../homelab-proxmox` checkout over the pin; `mise run setup` restores it.

## What each role does

- **`elastic_preflight`** — asserts only. `vm.max_map_count` is high enough
  (naming the real fix — rebuild the core repo's template — instead of letting
  ES exit with an error that reads like an application fault), and the stack
  passwords, encryption key and Kibana certificate inputs are present.
- **`es_certs`** — generates the internal CA and node certificate with
  `elasticsearch-certutil` in a throwaway container, verifies the chain with
  `openssl verify` before distributing anything, and pushes the CA to every
  host. Caches to `.certs/` so it never regenerates against a live cluster.
- **`elasticsearch`** — renders the compose project and per-node `.env`, then
  brings up the single node with TLS on both transport and HTTP.
- **`es_security_bootstrap`** — sets the `kibana_system` password and applies
  the single-node zero-replica override to Fleet's `@custom` component
  templates.
- **`kibana_tls`** — obtains a Let's Encrypt certificate for `kibana_fqdn`
  (`kibana.<zone of nextcloud_domain>`) with certbot and Cloudflare DNS-01,
  using this repo's own Cloudflare token. certbot's systemd timer renews it;
  the deploy-hook copies the new pair into Kibana's certs directory and
  restarts the container. Off with `kibana_tls_letsencrypt: false`.
- **`kibana`** — brings up Kibana on port 443 serving that certificate, or on
  5601 with the internal node cert when Let's Encrypt is off.
- **`fleet_bootstrap`** — scripts, through Kibana's API, everything the Fleet
  setup wizard would do by hand: initialisation, the default output (pointed at
  the real HTTPS endpoint, not the `localhost:9200` Fleet auto-creates), the
  agent policies, the System/Docker/Prometheus integrations, and the enrollment
  tokens. Every create is guarded by a GET-by-id, so it is safe to re-run.
- **`fleet_server`** — brings up Fleet Server on port 8220, reusing the same
  internal CA every agent already trusts.
- **`exporters`** — Prometheus exporters for what Elastic has no integration
  for: TrueNAS (via `graphite_exporter`) and Nextcloud's application metrics.
  Metrics ports bind to `127.0.0.1`; the agent scrapes them over loopback.
- **`elastic_agent`** — installs or updates the agent to match `stack_version`,
  enrolls it with Fleet against the right policy for its group (`monitoring`
  gets the Prometheus integration, everything else the general policy), and
  stops any leftover Grafana Alloy service from the previous design.

## Linting

```bash
mise run lint:ansible     # ansible-lint (production profile) + syntax-check
```

Role variables are prefixed with the role name (`exporters_*`,
`elastic_agent_*`, `_elastic_preflight_*` for registers); the ported `es_*`
names live in `inventory/group_vars/` instead, which keeps them visible
cross-role and the linter satisfied.
